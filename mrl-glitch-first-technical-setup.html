Can I develop for Quest 3 on a Mac?

Yes. Unity runs natively on Apple Silicon (M1/M2/M3) via Unity Hub, and Meta officially supports Unity development for Quest on macOS (including Meta XR Simulator and Meta Quest Developer Hub on Mac).

On Windows, many people use Quest Link to run content directly from the editor inside the headset.
On macOS, the typical workflow is:

  • Use Meta XR Simulator inside Unity for quick tests.
  • Use Build & Run to deploy an Android build (APK) to the Quest 3 when you want to test on the real headset.

1. User vs. Developer: two layers

As a user (no development):

  • You need:
    • A Meta Quest 3 headset.
    • A Phone (iOS or Android).
    • The Meta Horizon on your phone (this is the companion app; In mid-2024, Meta renamed the old “Meta Quest” mobile app to “Meta Horizon” and changed the icon/UI.).
    • A Meta account
      • You sign into the Meta Horizon app on your phone with your Meta account.
    • You pair the app with your Quest 3 (Settings → Devices → select headset).
  • Basic flow:
    • Turn on the headset → follow the initial setup (Wi-Fi, controllers, boundary/guardian, tutorial).
    • Pair the headset with the mobile app (Menu → Devices → select your Quest; wait for “Connected”).
      • During the very first setup of the Quest 3, the headset itself will also ask you to:
        • either log in with an existing Meta account, or
        • confirm / finish the login that started from the phone app.
    • Use the headset as a normal consumer device: store apps, MR experiences, games, etc.

As a developer (Unity + Quest 3):

  • You are still a “normal user”, plus:
    • A Meta Developer Account (same login, but with a developer organization created). To be a Quest / Horizon developer, your Meta account must be verified using one of two options:
      • add a payment method (credit card, not PayPal), or
      • set up two-factor authentication (2FA) via phone/SMS or authenticator app.
    • Developer Mode enabled on the headset.
    • Meta Quest Developer Hub (MQDH) installed on your Mac, logged in with the same Meta developer credentials as the headset.
    • Unity with Android support on your Mac (2022.3.15f1+ or Unity 6.x LTS, with Android Build Support).

Once those exist, you can build and deploy your own MR apps to the Quest.

2. What’s needed to develop with Unity on Mac (dev mode)

For Unity + Meta Quest 3 development on your Mac M3:

  1. Unity environment

    • Install Unity Hub, then a Unity LTS version supported by Meta:
      • Prefer Unity 2022.3 LTS (2022.3.15f1 or later) or Unity 6000.x LTS.
    • Unity has two release families:
      • Tech Stream – new features, less stable, changes quickly.
      • LTS (Long Term Support) – production-focused: stability, bug and security fixes, long maintenance.
    • When installing Unity via the Hub:
      • Go to Installs → Install Editor → choose 2022.3.xxf1 LTS (Apple Silicon).
      • Add Android Build Support (Android SDK, NDK, OpenJDK).
      • Optionally add Mac Build Support (IL2CPP) if you also want native macOS builds.

  2. Developer account & organization

    • Go to the Meta developer site and create a developer organization linked to your Meta account.
    • Verify the account (credit/debit card or phone code).

  3. Developer Mode on the headset

    • On your phone: open Meta Quest app → Menu → Devices → [your Quest] → Headset Settings → Developer Mode → toggle ON.

  4. Meta Quest Developer Hub (MQDH) on Mac

    • Download and install MQDH for macOS from the official Meta developer site, or:
      • Use Homebrew: brew install --cask meta-quest-developer-hub.
    • Open MQDH and log in with your Meta developer credentials (same account as on the headset).

  5. Connect Quest 3 to MQDH

    • Connect Quest 3 ⇆ Mac via USB-C.
    • Put on the headset → accept USB debugging / file access prompts and select “Always allow from this computer”.
    • In MQDH, open Device Manager and confirm the headset appears as Active (green).
    • From MQDH you can see realtime device logs, install APKs via the Apps tab, and enable ADB over Wi-Fi for cable-free development.

At this point you are “fully dev-enabled”: Unity can build Android apps, and MQDH + ADB let you install and debug them.

3. End-to-end flow for the first MR test

Goal of this first prototype:

Mixed Reality scene with passthrough + hand tracking + a static cube in space, no interaction yet.

High-level steps (already accomplished, but good to document):

  1. Create Unity project for Quest

    • New Unity 3D project.
    • Set Build Target to Android.
    • Install and enable XR Plug-in Management → OpenXR for Android.

  2. Install Meta XR SDK

    • Import Meta XR Core / All-in-One SDK into the project.
    • Run the Project Setup Tool to auto-configure player settings, OpenXR features, and recommended options for Meta Quest.

  3. Add XR “building blocks”

    • Add the Camera Rig / Interactions Rig building block to the scene (this becomes your XR origin + tracking).
    • Add the Passthrough building block → enables color passthrough so you see your real room with virtual content over it.
    • Add the Real Hands building block → enables hand tracking visuals and basic input, using the same rig.

  4. Add a simple virtual object

    • Create one Cube in the scene.
    • Place it roughly at head height / slightly in front (initially fixed coords).
    • No interaction logic yet (no grabbing, no physics beyond default).

  5. Build & Run to Quest 3

    • In Build Settings, add the open scene.
    • Select your Quest as the Run Device (via USB).
    • Click Build and Run → Unity builds an Android app and installs it on the headset.
    • In the headset, find the app under Apps → Unknown Sources, or it auto-launches after install.

  6. Resulting experience (current state)

    • You see your real environment via passthrough.
    • A virtual cube floats in front of you (MR).
    • Hand tracking is active (virtual hands visible), but:
      • you don’t yet interact with the cube (no grab, no poke, no click);
      • the cube is more like a spatial anchor / visual test.

This is a good “Hello MR” baseline: color passthrough + hands + a simple object.

Note: On macOS you can also use Meta XR Simulator to test your scene directly in the Unity Editor (simulated headset + hands) without building every time. For final validation on the real hardware, use Build & Run to deploy to the Quest 3.
